Graph Path Similarity Examples

This page uses toy paths on a simplified maze. It illustrates the rules for the real graph-path audit, where the real nodes come from docs/geometry/maze_mesh_centroids_1344.txt. 

raw Unity path -> nearest graph nodes -> split invalid gaps -> collapse repeats -> directed edge sequence -> route signature

Primary rule

  • Use successful trials only.
  • Use success_after_success when inferred start labels are needed.
  • Do route-definition work on train/validation only.
  • Do not bridge invalid gaps or invent edges.

1. Same start/goal, same route

Use: exact route-family repeat inside one (start, goal).

Claim: useful for within-condition route decoding, but endpoint confounds remain controlled by design only if alternatives exist.

2. Same start, different goal, shared initial segment

Use: tests shared future movement, but initial overlap may just be start/view/first-action coding.

Verdict: good sensitivity case, weak standalone evidence.

3. Different start, same goal, shared terminal segment

Use: terminal overlap across starts.

Verdict: useful, but may be goal coding unless matched against same-goal low-overlap paths.

4. Different endpoints, shared middle segment

Use: best compositional test if enough data exists.

Claim: cue geometry covaries with a reusable future path component beyond endpoints.

5. Same edge set, different order

Lesson: directed-edge Jaccard can say paths are similar even when traversal order differs.

Fix: keep ordered signatures and shared contiguous segments.

6. Invalid gap: do not bridge

Rule: split into two segments. No edge is added across missing/invalid samples.

Reason: interpolation can invent a route the monkey did not take.

Similarity features

Feature Captures Failure mode Use now?
Exact corridor/branch signature Same ordered coarse route Too sparse if graph too fine Primary first count
Directed-edge Jaccard Shared directed edges, ignores timing Ignores order and repeats Good support metric
Shared contiguous segment Reusable path component Initial/terminal overlap confounded by start/goal Best for examples and H1b screen
Graph-DTW Soft sequence alignment More assumptions; can hide overfitting Sensitivity only

Pseudopopulation example

route_family R inside start=P2, goal=P5
session 20180702 contributes its selected cells from one eligible source trial
session 20180705 contributes its selected cells from one eligible source trial
...
concatenate selected-cell blocks -> synthetic cue vector labelled R

The label is the shared route family, not one real trial's exact path. This can test condition-level route-family discrimination, not intention or simultaneous population dynamics.
