4. Shared objects where the science really is shared

Implemented

The development split-access guard

src/neuro/place195_split_access.py now owns the unchanged reader/validation logic and the SplitFilteredAccess, SplitFilteredAudit and SplitAccessError objects.

Seven scientific callers import it explicitly. The old script is an import alias, preserving module/class identity—not a second implementation.

Next slices

Visible study implementations

Move a coherent study family into src/neuro/studies/, then leave thin launchers in scripts/. Extract further shared objects only after their invariants and callers agree.

Most scientific bodies are still in scripts/. This is acknowledged migration work, not the finished design.

Good reasons to share

  • The same definition of source-trial identity and allowed splits.
  • The same assembly or evaluation semantics across actual callers.
  • One correction should apply to every user of that method.

Reasons to keep methods separate

  • Different targets, cohorts, conditioning or null hypotheses.
  • Different independent units or admissible timing windows.
  • Similar-looking code that implements different scientific contracts.

No catch-all utils.py. Reusability determines a module's role inside src/; it does not decide whether scientific logic deserves to be visible there.

Report + companion notebookVisible intermediate shapes/checks and explanations beside results. Notebook not yet built.

Target flow. The existing manuscript builder currently reads tracked aggregates and historical figures directly; it does not import scientific runners or fit models.

The first notebook should explain approved report views from tracked aggregates. It should restart and run in order, show where each result comes from, and clearly distinguish a measured variable from a derived feature or interpretation.

Computational transparency is not formal neural-state observability. Creating a notebook does not authorize new data access, fitting or saved-model reanalysis.

7. Preserve evidence, not the old clutter

Historical identity stays historical

Legacy paths remain compatibility symlinks. Frozen protocols, original snapshots and receipts are not rewritten to make new locations pass old checks. Current callers hash the actual extracted implementation, not merely the alias.

Changed current source means historical approvals can be stale. Reproduction needs the recorded source/runtime/input contract—not a freshly blessed wrapper hash.

Private material stays untouched

No data/model/prediction, runtime, PDF, submodule or retained worktree cleanup. The unrelated untracked current-state report is excluded from publication.

Deleting a paper queue does not delete its ignored PDFs. Git recovery is not a private-data backup.

Known unresolved integrity issue

The frozen retrospective HTML already differed from its original committed milestone before migration. The current state is checkpointed without replacing those bytes. Its exact-hash assertion still fails; the expected hash was not weakened. Resolve this explicitly before calling the frozen milestone verified.

8. Review the design before expanding the migration

  1. Reading hierarchy: can you find the current report immediately, then move from week → study → evidence without interpreting filenames?
  2. Scientific ownership: is shared behavior visible in src/, while study-specific contracts stay explicit?
  3. Migration boundary: is it clear which files moved and which remain legacy? This draft intentionally does not claim a completed rewrite.
  4. Next extraction: choose one complete study family, preserve its provenance, and replace its script body with a launcher. Do not refactor all algorithms simultaneously.
  5. Publication gate: decide the frozen-file mismatch explicitly, then continue editorial work and define the notebook's approved inputs.

Recommended sequence: review this draft → migrate one scientific family → migrate its complete evidence package → build the companion notebook after its scope is agreed. Continue report editing independently; no scientific rerun is required by the directory design.
